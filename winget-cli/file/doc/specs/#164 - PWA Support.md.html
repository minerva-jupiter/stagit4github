      9

     12 ## Abstract
     13 
     14 This feature adds PWA (Progressive Web Application) support to winget. The goal is to allow users to install and maintain PWAs just like they would any other type of application on winget. As a first step, this would be available as an "experimental" feature to make it available to the community and receive feedback.
     15 
     16 ## Inspiration
     17 
     18 PWA adoption is extremely important in the Windows app ecosystem. It is also crucial that they are treated as first class citizens in the app ecosystem, just like any native application. Providing PWA support for winget is key to achieving this goal.
     19 
     20 ## Solution Design
     21 
     22 ### System requirements
     23 
     24 Windows 10 v2004 or newer
     25 Edge latest Canary build
     26 
     27 ### PWA YAML manifest
     28 
     29 The "InstallerType" field in the YAML manifest file specifies the type of the application. A new InstallerType "PWA" will be added to show that a given application is a PWA.
     30 
     31 Each PWA would have its own manifest YAML file. A sample manifest file would look like this:
     32 
     33 ```
     34 Id: FinancialTimesLimited.FinTimes
     35 Version: 1.0.0.0
     36 Name: AppInstaller FinTimes
     37 Publisher: Financial Times Limited
     38 AppMoniker: fintimes
     39 License: Test
     40 InstallerType: PWA
     41 MinOSVersion: 10.0.19041.0
     42 Installers:
     43 - Arch: x64
     44   Url: https://app.ft.com
     45   InstallerType: PWA
     46 ManifestVersion: 0.1.0
     47 ```
     48 
     49 ### Package generation
     50 
     51 A POST call is made to a web service (https://pwabuilder-win-chromium-platform.centralus.cloudapp.azure.com) with a JSON body containing the URL to the PWA. The web service packages the PWA and its assets into an unsigned MSIX. An example of the JSON body would be :
     52 
     53 ```
     54 {
     55     "url": "https://app.ft.com"
     56 }
     57 ```
     58 
     59 There are many more optional parameters that can be passed to this service. For more information, refer to the test website linked in the Resources section.
     60 
     61 ### Package installation
     62 
     63 The unsigned MSIX package and any other dependency packages are added for the current user and the application is silently installed on the user's system. The installation is done by calling the Windows API AddPackageByUriAsync() using the specific deployment options that allow unsigned packages.
     64 
     65 ### Flow of the install process
     66 
     67 1. User types the install command, eg. `winget install fintimes` (For the experimental version, the manifest will be passed as an argument)
     68 2. The URL from the manifest YAML file of the Financial Times PWA will be sent as a POST request to an internal web service that will generate an unsigned MSIX package. This MSIX package is downloaded onto the user's system.
     69 3. The generated package will then be silently installed as a Hosted App (Refer to resources for more on the Hostel App Model).
     70 4. The MSIX file is removed from the user's system.
     71 
     72 ## UI/UX Design
     73 
     74 Installing a PWA will be similar to installing other application types currently supported by winget, using the install command. The only difference in experience might be if the user passes a -i flag to get a more interactive experience. When this flag is passed, the user will be prompted to allow the PWA to be launched on install. This feature is provided because in order to register a PWA with Edge, it has to be launched once.
     75 
     76 An example of the interactive install would look like this:
     77 
     78 ```
     79 >winget install -i fintimes
     80 Found Financial Times [PWAtest.FinTimes]
     81 This application is licensed to you by its owner.
     82 Microsoft is not responsible for, nor does it grant any licenses to, third-party packages.
     83 Starting package install...
     84 <Progress bar>
     85 Successfully installed! Launching app now. This is a necessary step to complete installation.
     86 (App launches on Edge)
     87 ```

    103 ### Compatibility
    104 
    105 This is an additional functionality built on top of the existing implementation to allow the install of PWAs. Therefore we don't anticipate any breaking changes to the existing implementation.

    109 ## Potential Issues
    110 
    111 If the user navigates to the site before launching the installed PWA at least once (i.e. before registration with Edge), Edge might prompt them to install the PWA again.
    112 
    113 ## Future considerations
    114 
    115 1. We are looking into where the catalog of PWAs should exist, and the pros and cons of maintaining a separate catalog vs including PWAs on the existing catalog.
    116 2. We're testing this new integration technology with Edge first in 2020 and hope to have this debugged and contributed to the Chromium project early 2021.
    117 3. Sometimes there may be multiple versions of a PWA available. In such scenarios, we may allow a "force" option in the case where a user wants all of them to be installed.
    118 4. There will be a service developed in the future that updates all the PWA manifests whenever there is a breaking change in Edge or in the web service that generates MSIX packages.
