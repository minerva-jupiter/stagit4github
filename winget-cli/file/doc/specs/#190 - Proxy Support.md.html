      8 # Proxy support
      9 
     10 For [#190](https://github.com/microsoft/winget-cli/issues/190)
     11 
     12 ## Abstract
     13 
     14 This spec describes a feature to specify a proxy for winget to use when connecting to the internet.
     15 
     16 ## Solution Design
     17 
     18 A new command line argument will be added to specify a proxy to use during a particular invocation of winget.
     19 This functionality will first need to be enabled through an admin setting, similar to local manifests or hash override.
     20 
     21 An option to set a default proxy to use on every flow will be added, but it will require administrator permissions to be set.
     22 
     23 New Group Policy will also be added for IT admins to control the use of proxies.
     24 The policies will be similar to those we already have for sources, so that a specific proxy can be required or only a predefined set of proxies can be allowed.
     25 
     26 Proxies will not be used for the configuration features for now.
     27 Proxy settings in winget will not affect the behavior of installers themselves, so an installation may still generate traffic outside of the proxy.
     28 
     29 The proxy will be used to download the installers and access the sources.
     30 
     31 Since the APIs used for Delivery Optimization and MSIX deployment do not provide a way to specify a custom proxy, if a proxy is specified, we will change the use of those APIs to accomodate the proxy.
     32 For Delivery Optimization, a proxy will force use of WinINet instead.
     33 For MSIX deployment, the packages will be fully downloaded before deploying; this will require more network traffic than a streaming install of only the required bits.
     34 
     35 ## UI/UX Design
     36 
     37 We will add a command line argument taking the URI to the proxy.
     38 A separate argument will be available to disable the use of proxy if there is a default set.
     39 Both of these arguments will be disabled by default and require admin privileges to enable.
     40 
     41 ```
     42 > winget settings --enable ProxyCommandLineArgument
     43 > winget install Contoso.App --proxy https://127.0.0.1:2345
     44 > winget install Contoso.App --no-proxy
     45 ```
     46 
     47 To configure the default proxy, new `set` and `reset` subcommands will be added to the `settings` command.
     48 This will require admin privileges and does not require `ProxyCommandLineArgument` to be enabled.
     49 
     50 ```
     51 > winget settings set DefaultProxy https://127.0.0.1:2345
     52 > winget settings reset DefaultProxy
     53 ```
     54 
     55 The current default proxy will be added to the output `winget --info`.
     56 
     57 ## Capabilities
     58 
     59 ### Accessibility
     60 
     61 This should have no direct impact on accessibility.
     62 
     63 ### Security
     64 
     65 There is a possibility of an attacker using a malicious proxy to tamper with the data received from the source, or with the contents of the installer file.
     66 This is not much different from the risks of using a public network.
     67 The following mitigating factors will be in place:
     68 * (New) The ability to set a default proxy will be restricted to administrators, to prevent attackers from adding a proxy without the user realizing.
     69 * (New) A Group Policy will be available to block the use of proxies, require the use of a specific proxy, or limit them to an approved list.
     70 * Pre-indexed sources need to be signed, and the publisher is required to match during source update.
     71   When initially adding the source, administrator privileges are already required to limit misuse.
     72 * Pre-indexed sources include manifest hashes in the local database, to ensure that the manifest downloaded later is as expected.
     73 * For the Microsoft Store source, we use certificate pinning to ensure we are talking to the right server.
     74 * When communicating with REST sources, the certificate used by the source for HTTPS needs to match the domain.
     75 * Manifests include a hash of the installer that is validated before executing it.
     76   The ability to ignore installer hash mismatches is disabled by default, and enabling it requires administrator privileges.
     77 
     78 ### Compatibility
     79 
     80 No breaking changes to existing behavior.
     81 
     82 ### Performance, Power, and Efficiency
     83 
     84 There should not be any notable performance changes.
     85 
     86 ## Potential Issues
     87 
     88 A faulty or misconfigured proxy could impact most of winget's functionality, but it can be worked around by disabling the use of the proxy.
     89 
     90 ## Future considerations
     91 
     92 Things we may want to consider in the future:
     93 * Extend support for proxies to the Configuration feature
     94 * Add proxy support to the COM API
     95 * Add support for proxies that require authentication
     96 * Add the ability for admins to set multiple allowed proxies that a user can use
     97 * Add the ability to specify a different default proxy for each source
     98 * Use proxies with Delivery Optimization. This requires changes to the Delivery Optimization APIs.
