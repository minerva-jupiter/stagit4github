      8 # Management of package type dependencies
      9 
     10 For [#1287](https://github.com/microsoft/winget-cli/issues/1287)
     11 
     12 ## Abstract
     13 As a new step in the pursue of dependency management, the Windows Package Manager will take care of one of the four types of dependencies (Package) for most of the commands. The underlying logic of the code will prove useful when implementing the rest of the types and commands; since it will manage dependencies' graph building and validation, as well as the correct order of installation.
     14 
     15 ## Solution Design
     16 The Windows Package Manager will build the dependencies' graph and corroborate there's not a cyclic dependency, among other validations (depending on the command).
     17 
     18 ### Install:
     19 Install command will build the dependency graph at runtime, from installer information. It will report on the other three types of dependencies and manage package type installation/validation (for new/installed dependencies respectively).
     20 As a best effort, in case a cyclic dependency exists, Windows Package Manager will inform the user but try to install in some order; this is because most of the dependencies are at run time so there shouldn't present an issue on install.
     21 
     22 While building the graph, install command will verify:
     23 * Availability: the package declared as dependency will need to be an existing one.
     24 * Installed version: it will check for existing versions of the dependency and update if the minimum required version is bigger than the installed.
     25 * Version: minimum required version will need to be less or equal to the latest available one.
     26 
     27 Information will be shown about failures, existence or installation progress for each of the dependencies required.
     28 
     29 When installing from a local manifest, a dependency source will be required (using --dependency-source parameter), but only if the target has at least one package type dependency declared.

     55 ### Import:
     56 Import command will report all first level dependencies beforehand and after will work as install command for each of the packages found, iteratively. Ex. if packages *foo* and *foo1* are part of the import, dependencies for *foo* will be fetch and installed before continuing with *foo1*.

     87 ### Update:
     88 * Update one: will also work as install command, we need to check again for dependencies as the new installer can have new ones or bigger minimum required versions.
     89 * Update many: will work iteratively (as import).

    114 ## Capabilities
    115 Will manage package type dependencies installation for install, import and update commands.
    116 Will not manage or try to install any of the other types of dependencies (Windows Features, Windows Libraries, External).
