      1 # Undocked RegFree WinRT
      2 
      3 [![Build Status](https://dev.azure.com/microsoft/Dart/_apis/build/status/Undocked%20RegFree%20WinRT%20Nuget?branchName=master)](https://dev.azure.com/microsoft/Dart/_build/latest?definitionId=47851&branchName=master)
      4 
      5 Enable non-packaged desktop applications 
      6 to leverage user-defined Windows Runtime types via the use of the 
      7 application manifests down to RS2. 
      8 
      9 To achieve this, the package uses the detours library, detouring RoActivateInstance, RoGetActivationFactory,
     10 RoGetMetadataFile, and RoResolveNamespace and reimplementing the RegFree WinRT feature that is avaibale on windows version 19h1 and above. 
     11 The package will automatically place winrtact.dll to your build folder where your exe should be.  
     12 
     13 Initializing the detours on winrtact.dll
     14 - Native
     15 Initialization of the dll is taken care of automatically through ForceSymbolReferences. 
     16 
     17 - Managed
     18 For Managed code, one will have to initialize it manually by calling 
     19 Microsoft.Windows.UndockedRegFreeWinrt.Initialize();
     20 This will initialize the detours and load the catalog. 
     21 
     22 
     23 Example application manifest:
     24 Your application manifest should have the same name as, and be side by side to your executable.
     25 "your_exe_name".exe.manifest
     26 
     27 
     28 Example application manifest:
     29  ``` 
     30 <?xml version="1.0" encoding="UTF-8" standalone="yes"?>
     31 <assembly xmlns="urn:schemas-microsoft-com:asm.v1" manifestVersion="1.0">
     32   <file name="TestComponent.dll">
     33     <activatableClass
     34         clsid="TestComponent.Class1"
     35         threadingModel="Both"
     36         xmlns="urn:schemas-microsoft-com:winrt.v1" />
     37     <activatableClass
     38         clsid="TestComponent.Class2"
     39         threadingModel="sta"
     40         xmlns="urn:schemas-microsoft-com:winrt.v1" />
     41     <activatableClass
     42         clsid="TestComponent.Class3"
     43         threadingModel="mta"
     44         xmlns="urn:schemas-microsoft-com:winrt.v1" />
     45   </file>
     46 </assembly>
     47  ``` 
     48 
     49 Starting with Windows 10 19h1, the operating system has this feature by default and will use this information directly. Be sure to use [Windows version targeting](https://docs.microsoft.com/en-us/windows/win32/sysinfo/targeting-your-application-at-windows-8-1) so that the package automatically disables itself when this feature is available by default.

     51 ### Windows 8.1 Support (10/16/2020)
     52 Undocked RegFreeWinRT can now activate types down to Windows 8.1. However, there are some minor things to account for on Windows 8.1. 
     53 
     54 1) On Windows 8.1. you may encounter error 0x8007109A (This operation is only valid in the context of an app container) when activating your type. This is caused by the app container check that exists in windows 8.1 but not on later versions.
     55 This can be fixed by setting the linker option of your component that you're activating to /APPCONTAINER:NO
     56 Refer to 
     57 https://docs.microsoft.com/en-us/cpp/build/reference/appcontainer-windows-store-app?view=vs-2019
     58 https://docs.microsoft.com/en-us/windows/uwp/debug-test-perf/windows-app-certification-kit-tests#appcontainercheck
     59 for more information. 
     60 
     61 2) MTA to STA cross apartment activation needs additional advanced manifest and dll work on Windows 8.1. This work isn't required on later versions of Windows because of a feature called metadata based marshaling. 
     62 For cross apartment activation to work on Windows 8.1, you'll need to author your own proxy/stub dll for the component you're activating and include a classic COM registration in the manifest to register that proxy.
     63 Refer to 
     64 https://docs.microsoft.com/en-us/windows/win32/com/building-and-registering-a-proxy-dll
     65 for more information.
