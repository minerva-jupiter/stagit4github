Use in-proc winget in PowerShell module when running as SYSTEM (#3129)

This change uses the in-proc WinRT binaries and activation path when running as `SYSTEM` in the PowerShell module.  It also makes `Assert-WinGetPackageManager` succeed as long as the OS version is high enough in that case.

There are two known caveats with this that could be addressed in a future change if needed:
1. These newly added dlls are still dependent on the VC runtime, and thus will not work unless it has been installed. This seems acceptable for development scenarios. For shipping a module without this dependency, we will need to build a statically linked binary, but only on the internal, release pipeline.
2. The code currently doesn't behave well in an STA thread, meaning that when used from `SYSTEM` the module requires running PowerShell with the MTA option.
