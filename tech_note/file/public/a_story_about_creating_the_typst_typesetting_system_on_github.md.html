     20 # 経緯(長い駄文)
     21 ## 前史(TeX)
     22 大学でのレポートをwordで書きたくないと思った私はTeXに魅了されていました。
     23 WSLにTeX Liveをインストールし、TeXで大学のレポート等々をほそぼそと書いていました。
     24 そんな2024年の12月、私の所属するサークルが冬コミに向けて部誌を発行することになりました。
     25 自分の書いた記事が同人誌になるなんて夢のようでした。そのサークルは技術者コミュニティなので、記事はGitHubのプライベートリポジトリで管理され、提出形式はHTMLでした。
     26 ですが、締切が近いことや、GitHubに慣れていないメンバーもいたせいか、CSSの参照が破壊されてしまったりしました。またmainブランチへの強制プッシュなども行われて、非常に混乱してしまいました。
     27 また、完成した冊子を見ると、自分の記事もレイアウトが崩れてしまっていて、非常に悔しい思いをしました。そこで、完成のプレビューのPDFを吐くタイプの自動レンダリング組版システムを構築する決心をしました。
     28 そして、完成したのがTeXをPDFにコンパイルしてArtifactに投稿するシステムでした。
     29 ## TeXってさ......
     30 しかしながら、TeXの酷いエラーやTeX Liveの重さがネックとなり始めました。
     31 極めつけは本格的に大学の実験レポートが始まったことでした。2週間に1回か2回PDFにして14ページ程度もあるレポートにぎっしりの文字と数式と図表を書く必要が発生したのです。それはTeXの長い記法にうんざりするには十分でした。
     32 ニュートンの運動方程式を書くために、
     33 ```LaTeX
     34 $ m \frac{d^2 x}{d t^2} = F $
     35 ```
     36 って書くなんて冗長じゃないですか！
     37 あわよくば、暗算しながら書けるくらいの使いやすさで書きたい！
     38 そう思っていたときに私はTypstに出会いました。
     39 typstで書くとこれですみます。
     40 ```typst
     41 $ m (d^2 x)/(d t^2) = F $
     42 ```
     43 
     44 ## Typstの紹介
     45 > Typst is a new markup-based typesetting system that is designed to be as powerful as LaTeX while being much easier to learn and use.
     46 
     47 レポジトリのREADME.mdより
     48 らしいです。意訳すると、「Typstは新しいマークアップを基とした、LaTeXみたく強力なそしてもっと学びやすくて使いやすいタイプセッティングのシステムです」です。(あんまり正確な翻訳じゃないかも)
     49 そして何より、これはRust製です。そこが素晴らしい(Rust大好き人間なので)
     50 正直なところ、まだ未発達な部分も多いので、枯れるまで開発されて、やっと使われるようになるかのスタートラインだとは思うのですが、それでも、こういう新しい技術は使ってみたくなります。
     51 繰り返す文章をfor文で書けたり、数式を美しく簡単に書けたりと、そそる機能が満載です。
     52 二点、問題点を挙げると、
     53 1. テンプレート等が未発展
     54 2. 日本語が使いにくい
     55 です。テンプレートは自分なりに形成していけばよいのですが、警告メッセージにすべての日本語文字を出すのはやめてほしいですね。あとは、フォントの指定なのですが、規定の欧文フォントだと日本語を使えないので、かなり必須なところが設定が面倒です。typst.appでは日本語フォントの指定は`Noto Sans CJK JP`とできます。しかし、ローカルでのコンパイルとなると、話が変わります。私はtypstのシステムにフォントを追加する方法がわからなかったので、typstにコンパイルをお願いするときにttfファイルの在処を`--font-path ~/.fonts`で指定してコンパイルしています。ただ、毎回面倒だし、bash-completionで入力できないのでbashスクリプトを書いています。
     56 ということで、まだまだ発展途上ですが、私は使いたい(というかTeXにうんざりしている)ので、Typstで組版システムを構築しようというのが今回の流れです。

     58 # 設計
     59 
     60 まず、はじめにこのシステムの設計思想です。
     61 目的として
     62 
     63 - Typstの実行環境が手元にない場合でも使いやすいこと
     64 - 一つの絶対的なコンパイル手法を存在させること
     65 - Typstの利点を活かせること
     66 
     67 を設定しました。
     68 したがって要件定義は
     69 
     70 - GitHubのPRにpushするとすぐにプレビューができる形であること
     71 - レンダリング手段が統一されていること
     72 - typstをネイティブに叩いて変換を行うこと
     73 
     74 となりました。
     75 ## システムの設計
     76 上記より、今回は前回のシステムを踏襲するような形で書きたいと思います。
     77 また、一部技術的な問題で達成できない目的があります。
     78 ```mermaid
     79 flowchart TB
     80     User -->|push to branch| PR
     81     PR --> Workflows
     82     SelfHosted --> typst
     83     typst --> Artifact
     84     typst --> Log
     85     Artifact -->|URL| PR
     86 
     87     subgraph GitHub
     88         PR
     89         Workflows
     90     end
     91 
     92     subgraph Workflows
     93         SelfHosted
     94         Artifact
     95         Log
     96     end
     97 
     98     subgraph SelfHostedRunner
     99         Docker
    100     end
    101 
    102     subgraph Docker
    103         typst -->|--font-path| font[~/.fonts]
    104         typst 
    105     end
    106 ```
    107 これを基に構築をすすめていきます。
    108 ですが、コンパイル速度の問題と、SelfHostedの部分が私のサーバのリソースと向き合った結果、足りない可能性が出てきたので、TypstをDockerの中ではなくて、SelfHostedサーバのネイティブ上にインストールかとおもっています。(なおSelfHostedサーバ自体がVMなので安全性は確保される)
    109 # SelfHostedサーバの準備
    110 一家に一台はあるであろう、自宅サーバに適当なVMを立てて、セットアップします。
    111 UbuntuServerを使いました。そこにDockerとTypstをインストールして、あとはGitHubのActions/RunnerからSelfHostedRunnerを追加するボタンを押せば手順やトークンが出てくるのでそれに従えば良いです。
    112 
    113 ## typstのインストール
    114 UbuntuServer上では
    115 ```
    116 sudo snap install typst
    117 ```
    118 で終わります。Rustをインストールしてビルドしたいけど、環境を統一したいので、これ一択ですね。

    120 # Workflow
    121 SelfHostedでtypstを実行するものを作成します。
    122 なお、リリースビルドはSelfHostedだと怖いので、GitHubがホストしているRunnerにFontを入れて、Dockerでtypstのイメージを引っ張ってくる形にして安定を取りたいと思います。
    123 完成品のworkflowはリポジトリに置いてあるので、そちらを見て貰えば良いです。
    124 基本的には先人が作ったactionsの組み合わせで十分です。
    125 というか、前回までの積み上げがあるとはいえ、workflowがバグ無しで完璧に動作したのめちゃくちゃ気持ち良い。

    127 # fonts
    128 これがかなりの鬼門でした。Log上では動作しているので、わからないのですが、出力されたPDFを見ると、文字化けしてしまって□ばかりが並んでいるものになっていました。
    129 結論から言うとダウンロードしてサーバに入れていたフォントが悪かったのですが、ちゃんと動作するフォントと動作しないフォントがあって、大変でした。
    130 私はNoto Sans JPを愛用しているのですが、Google fontsからのダウンロードをworkflowができない点が問題でした。そして、埋め込み用のotfファイルをダウンロードしてもtypstが読み込めなかったです。
    131 NotoSansCJKのリポジトリから様々にotfファイルやttfファイルをダウンロードして入れてみましたが、細っそいフォントで描画されるのが関の山でした。しかし、LaTeXからTypstに移行した先人でNoto Sans CJK JPをインストールした方のQiitaを発見し、そのリンクのおかげで使えるようになりました。ここがこの記事で一番時間がかかりました。
